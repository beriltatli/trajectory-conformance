# Trajectory conformance monitoring on ADS-B data: a technical report

## 1. Problem

An air traffic controller needs to know when an aircraft starts to leave the trajectory it is
expected to fly, early enough to act, and without being interrupted by aircraft that are merely
flying normally. This project asks whether a model-based monitor (an interacting multiple model
(IMM) tracker scored against learnt route norms) does that better than a fixed cross-track
distance alarm, on real surveillance data, by flight phase, at a fixed false-alert budget.

The question is framed as an operator would use it: **detection rate within 600 s of the onset of
a deviation, at an alert budget of 2 false alerts per flight-hour, per phase (climb, cruise,
descent)**, with the operating point chosen on one day and reported on another.

## 2. Data

- **OpenSky Network state vectors** (Schäfer et al., IPSN 2014), 10 s snapshots, a 5 x 7.5 deg box
  around Frankfurt (EDDF, EDDM, EDDL, EDDK, EDDS), 12:00-18:00 UTC on six consecutive Mondays,
  2022-05-23 to 2022-06-27. About 3,400 flights and 1,400 flight-hours a day.
- Cleaning: stale rows (repeated position timestamps), flight segmentation at 10 min gaps,
  coverage holes never counted as monitored time (`DATA.md`, NOTES.md phase 1).
- **Licence.** Non-profit research use; the data and anything derived per flight stay local
  (`data/` is not in git; the replay of real traffic is served on localhost only). Only
  aggregate results are published. The public demo runs on synthetic traffic generated by
  `synth/traffic.py`, which is not fitted to OpenSky data.

## 3. Method

```
state vectors -> clean, segment -> IMM tracker (CV / CA / turn) -> follow reference path ->
6 residuals (cross-track, track angle, altitude, vertical rate, ground speed, ETA)
-> each mapped to its empirical tail rarity -> score = rarest component
-> threshold per phase -> alert management (2-update persistence, 300 s hold-off,
   re-presentation every 300 s) -> alerts
```

- **Tracker.** Genovese (2001) CV-CA-turn IMM, with fixes for irregular update intervals,
  mixing a 6-state CV into 9-state models, Joseph-form updates and a kinematic gate (NOTES.md
  phase 2). Streaming and whole-flight runs agree bit for bit.
- **References.** Flights are keyed by how they enter and leave the region (airport or 50 km
  boundary gate). Pairs with at least 5 tune-day flights get a median path and per-station
  norms (median and robust sd of each residual). Tune-day flights are scored against their
  pair's reference rebuilt without them, and the tails are cross-fitted in two folds, so the
  thresholds are not chosen on in-sample residuals.
- **Baselines**, all with the same alert management: never alert; a single CV Kalman filter
  scored by its NIS; ETA deviation; a **fixed cross-track distance** from the same reference
  path, the operational baseline.
- **Injected deviations.** On every reference flight, one lateral (2-30 deg heading offset),
  one vertical (250-2,000 ft/min) and one longitudinal (10-40 kt) deviation, each on its own copy
  of the real flight, so real noise, gaps and manoeuvres remain. A violation is 1 NM laterally or
  longitudinally (RNP 1) or 300 ft vertically.

## 4. Evaluation protocol

- **Detection** = an alert within 600 s of onset at a row where the same detector on the
  uninjected flight was not already exceeding. **False alert** = an alert on an uninjected
  flight (an upper bound: real flights deviate too). Monitored time excludes coverage holes.
- **Operating point**: per phase, of the thresholds within 2 alerts per flight-hour on the
  tune day, the one with the highest tune-day detection. Applied unchanged to the test day.
- **Rolling evaluation**: tune on one Monday, test on the next, five folds. The configuration was
  frozen before the three earliest test days (2022-05-30, 06-06, 06-13) were downloaded; the
  design had been revised while looking at 06-20 and 06-27, so those folds are reported but not
  used for the headline.
- **Uncertainty**: 95% intervals from a bootstrap that resamples flights (a flight's false
  alerts, monitored time and three events together), stratified by day; differences between
  detectors are paired (same flights, same injected events). Day-to-day spread is reported
  separately, because the flight bootstrap does not cover it.
- **Leakage checks**: references, airports, tails, thresholds, R and the fusion offset come
  from tune days only; phase labels are causal (trailing 60 s); the 06-20 -> 06-27 fold
  reproduces the original phase 4 results exactly. Two limits remain and are stated, not fixed:
  the origin-destination key uses the whole uninjected flight (standing in for the filed flight
  plan), and most test flights are the same scheduled services as a week earlier.
